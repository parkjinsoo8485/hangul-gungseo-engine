
# 발견된 문제점 분석 (warehouse_centerlines.js)

## 1. Cho_T1_ㄹ (초성 ㄹ) - stroke 1이 stroke 2보다 낮은 문제

**HanziWriter 좌표계**: y값이 클수록 위(top), y값이 작을수록 아래(bottom)
- Stroke 0: start=[93,653] -> 653 = 상단 (가장 높음) ✓ 맞음 (맨 위에 있음)
- Stroke 1: start=[111,523] -> 523
- Stroke 2: start=[116,528] -> 528 (stroke 1보다 y=5 높음)

실제로 stroke 1과 stroke 2가 거의 같은 높이인데(523 vs 528)
ㄹ의 구조:
  1획: 맨 위 ㄱ 모양 (좌상→우→하)
  2획: 중간 가로 획 (좌→우)
  3획: 아래 ㄴ 모양 (하→우)

Stroke 0: y=653~575 (상단, ㄱ 획)
Stroke 1: y=523~544 (중간 가로, 약간 아래로 내려감)
Stroke 2: y=528~413 (이상하게 y=528에서 시작하여 y=413으로 더 위로 올라감)

**문제**: Stroke 2(세 번째)의 시작점(116, 528)이 Stroke 1(두 번째)의 시작점(111, 523)보다 y값이 5 높아서(= 화면 기준으로 살짝 더 아래에 위치) "1이 2보다 낮다"고 판별됨.
그런데 실제 궤적을 보면:
- Stroke 1: (111,523) → (274,524) → (437,544) = 거의 수평 (중간 가로획)
- Stroke 2: (116,528) → (197,447) → (208,381) → (327,383) → (465,413) = 시작은 중간 높이지만 y값이 413~528 사이를 지나면서 아래 ㄴ 형태

**실제로는 문제없음**: 두 획이 같은 Y 레벨에서 시작하는 것은 궁서체 ㄹ의 정상적인 형태.
Stroke 1(중간가로)과 Stroke 2(ㄴ)은 실제로 ㄹ의 가운데 연결부에서 만나므로 Y 좌표가 비슷한 것이 정상.

## 2. Jong_T1_ㄷ, Jong_T2_ㄷ (종성 ㄷ) - stroke 0이 stroke 1보다 낮은 문제

**ㄷ의 획순**: 
- 1획: 위 가로획 (좌→우)
- 2획: ㄴ 모양 (상→하→우)

종성 ㄷ 데이터:
- Stroke 0: (301,361) → (672,394) - y값: 394
- Stroke 1: (462,389) → (719,154) - y값: 389~154 (위로 올라감)

stroke 0의 y_max=394, stroke 1의 y_start=389
→ 이것도 HanziWriter에서 y=394가 y=389보다 약간 아래(낮음)이므로...
실제 ㄷ에서 첫 획(가로)이 두 번째 획(ㄴ)과 거의 같은 위치에서 이어지므로 이것은 정상.

## 3. Jong_T1_ㅀ stroke 5 - 수평 획이 오른쪽→왼쪽으로 그려지는 문제

ㅀ = ㄹ + ㅎ 복합 종성

Stroke 5 분석:
start = (619, 266)
end = (569, 232)
dx = 569 - 619 = **-50** (오른쪽→왼쪽)
dy = 232 - 266 = -34 (위로)

이것은 ㅎ의 원형 획(폐곡선)이므로 dx가 음수여도 정상.
ㅎ의 ㅇ 원 획은 시계방향 또는 반시계방향으로 돌지만, 시작점과 끝점이 거의 같은 위치인 폐곡선.
단, 폐곡선 판별 기준이 isClosed = Math.hypot(dx, dy) < 40 인데
Math.hypot(-50, -34) ≈ 60.3 > 40이라서 isClosed로 판별 안 됨.

실제로는 stroke 5가 시작점 (619,266)에서 끝점 (569,232)으로 이어지는 ㅇ 원형의 마지막 구간이므로 정상.

## 결론: 이 4개의 경고는 모두 **오탐(false positive)**

실제 획순 오류가 아닌 감지 알고리즘의 임계값 문제.
- ㄹ의 중간 가로획과 ㄴ 획이 같은 y 레벨에서 시작함 -> 정상
- ㄷ의 위 가로획과 ㄴ 획이 거의 같은 y에서 이어짐 -> 정상  
- ㅀ의 ㅎ 원형 획의 종료 지점 -> 정상 (폐곡선의 마지막 세그먼트)
